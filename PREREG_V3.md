# Pre-Registration Plan: Phase 1 & 2 Debugging and Empirical Study Addendum (v3)

**Date:** 2026-10-25  
**Version:** 3.0  
**Scope:** Debugging suspicious results, fixing contradicted claims, testing dense truncation, evaluating OCR configuration effects, and redesigning heavy paraphrases.

---

## 1. Core Principles & Safeguards

1. **Zero Fabrication & Strict Traceability**: Every number in any table, figure, or text fragment must be programmatically generated by scripts writing to `results/v3/`. No manual editing or rounding up.
2. **Frozen Test Split**: The held-out test split (313 SROIE receipts, 500 COCO distractors = 813 test items, 306 probes) is strictly frozen. Code will assert that test items and test probes never enter any parameter fitting, tuning, or calibration routine.
3. **Cluster-Aware Resampling**: All queries targeting the same item ID belong to the same cluster. Bootstrap resampling ($B=2{,}000$ minimum) and cross-validation splits will strictly cluster by item ID.
4. **Forking-Paths Accounting**: Every parameter combination, hyperparameter sweep, and model variation attempted will be logged in `CONFIG_LOG.md`.

## 2. Phase 1 Experiments

### Experiment 1.1: OCR CER/WER Sanity & Normalization
- **Type**: Diagnostic / Exploratory.
- **Hypothesis**: The reported high error rates (CER = 0.4519, WER = 0.6503) for Apple Vision OCR on SROIE receipts are artificial artifacts of bounding-box spatial line concatenation vs. OCR vertical reading order and the absence of text normalization.
- **Method**:
  - Recompute CER and WER using `jiwer` with standard text normalization: lowercasing, collapsing consecutive whitespace, and stripping leading/trailing punctuation.
  - Evaluate both concatenated text and line-order aligned text.
  - Save 20 random (Ground Truth, Clean OCR, Degraded OCR) triples side-by-side to `results/v3/ocr_samples.md` for human inspection.
- **Decision Rule**: Report corrected CER/WER. If normalized CER drops substantially ($\le 0.15$), document that Apple Vision OCR transcriptions are fundamentally accurate and explain why BM25 achieves high retrieval accuracy (MRR > 0.80).

### Experiment 1.2: Dense Proxy Sequence Truncation & Chunked Retrieval (MaxP)
- **Type**: Confirmatory.
- **Hypothesis**: Dense embedding collapse on receipt documents is partly driven by sequence length truncation (loss of tail tokens exceeding the 512-token limit of MiniLM and BGE) rather than pure semantic drift.
- **Method**:
  - Measure document token length distributions under MiniLM and BGE tokenizers.
  - Report percentage of documents truncated and mean percentage of tokens lost.
  - Implement and evaluate chunked dense retrieval: partition receipt text into overlapping windows of $\le 256$ tokens with 32-token overlap, compute embeddings per chunk, and aggregate using Max-Pooling over chunk similarity scores (MaxP).
  - If available, evaluate long-context dense retrieval using `BAAI/bge-m3` (8,192 token limit).
  - Re-evaluate retrieval MRR and the numeric-heavy / short-probe error attribution under chunked dense retrieval.
- **Decision Rule**: If chunked dense retrieval (MaxP) improves dense clean MRR by $\ge 0.10$ and narrows the gap with BM25 on clean text, revise the "tokenization bottleneck" claim in the claims ledger to state that sequence truncation is a primary driver of dense proxy failure on structured receipts.

### Experiment 1.3: OCR Engine Configuration & Language Correction Effects
- **Type**: Exploratory.
- **Hypothesis**: Apple Vision's native language correction (`usesLanguageCorrection = true`) hallucinates valid dictionary words when given optically degraded or blurred images, explaining why vocabulary-based reliability ($r_{\text{ocr}}$) inverts from AUROC = 0.9948 on synthetic character noise to AUROC = 0.2674 on optical blur.
- **Method**:
  - Run Apple Vision OCR on the 626 SROIE receipt images under 4 configurations:
    1. Accurate level, Language Correction = True (Default)
    2. Accurate level, Language Correction = False
    3. Fast level, Language Correction = True
    4. Fast level, Language Correction = False
  - Compute normalized CER/WER and retrieval MRR (BM25 and Dense) under each configuration.
  - Recompute observable reliability ($r_{\text{ocr}}$) AUROC for discriminating clean from degraded text under each setting.
- **Decision Rule**: If AUROC is significantly higher with Language Correction disabled, report language correction as the direct cause of heuristic reliability failure.

### Experiment 1.4: Heavy-Paraphrase Redesign (Answerable Question-Style Queries)
- **Type**: Confirmatory.
- **Hypothesis**: The near-zero performance (MRR $\approx 0.009$, matching random baseline 0.0090) of heavy paraphrases in v2 was caused by aggressive token stripping that deleted core identifying facts. Redesigning heavy paraphrases as answerable question-style queries (<15% token overlap, identifying a unique entity) will yield valid, non-zero retrieval benchmarks.
- **Method**:
  - For each probe, generate a natural language question querying a specific factual field (vendor name, receipt total, transaction date, or distinct line item) that shares $<15\%$ lexical tokens with the receipt text.
  - Programmatically verify that the factual answer uniquely identifies the target receipt across all 626 documents (single-target constraint).
  - LLM: `gpt-4o-mini` with `temperature=0.0`. Prompt and seed frozen.
  - Output 50 random queries to `results/v3/heavy_audit_sample.csv` for human inspection.
- **Decision Rule**: Heavy paraphrases are acceptable if clean retrieval MRR exceeds $0.05$ (statistically distinguishable from the random baseline $H_{813}/813 = 0.0090$).

### Experiment 1.5: Statistical Hygiene & Permutation Test Scaling
- **Type**: Methodological.
- **Method**:
  - Scale paired permutation tests from $N_{\text{perm}} = 10{,}000$ to $N_{\text{perm}} \ge 100{,}000$ iterations to eliminate permutation floor artifacts ($p = 0.0011$ and $p = 0.00040$).
  - Report exact $p$-values down to $p < 10^{-5}$.
  - Re-apply step-down Holm-Bonferroni correction within each experimental family.

### Experiment 1.6: Conformal Risk Control & Data Hygiene
- **Type**: Confirmatory.
- **Method**:
  - Ensure cluster-awareness: all query variants and noise conditions for any target item must remain exclusively in the calibration half or test half of any split.
  - Implement finite-sample corrected conformal risk control (e.g., $(n+1)$ correction or Learn-then-Test with Clopper-Pearson / Hoeffding bounds).
  - Precisely define the non-escalated miss risk:
    $$\text{Risk}(\tau) = \mathbb{E}\left[\mathbb{I}(\text{rank}^{(1)} > 1) \mid \Delta_{1,2} \ge \tau\right]$$
  - Across 200 random cluster-aware splits, report: mean test risk, fraction of splits satisfying test risk $\le 0.05$, escalation rate, MRR, latency, with 95% CIs.
  - Decision Rule: Claim "guarantees" or "controls risk" if and only if mean test risk $\le 0.05$ AND empirical coverage is statistically compatible with the nominal confidence level ($1-\alpha \ge 0.90$). Otherwise, report factually as empirical calibration without guaranteed coverage.
