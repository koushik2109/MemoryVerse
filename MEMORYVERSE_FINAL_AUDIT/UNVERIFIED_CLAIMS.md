## 2. ITEMIZED CLAIMS AUDIT

### Claim 1: "Two-stage cascade achieves 16.20 ms latency (15.4x speedup over native ColQwen2)"
- **Original Claim:** The manuscript claimed that deploying a two-stage cascade ($K_1=50$ Word BM25 $\to$ ColQwen2) slashes latency from 249.21 ms to 16.20 ms.
- **Audit Finding: UNVERIFIED (ANALYTICAL MODEL ESTIMATE).**  
  In `scripts/gapfill_t2_04_fusion_cascade.py` (lines 105–125), latency was calculated as an analytical sum:
  $$\text{Latency} = 0.87\text{ ms (Apple M2 CPU)} + 50 \times \left(\frac{249.21\text{ ms (Tesla T4 GPU)}}{813}\right) = \mathbf{16.20\text{ ms}}$$
  This was never measured end-to-end in a live pipeline. It combined CPU time on an Apple M2 laptop with scaled GPU time on a remote Tesla T4 GPU, omitting PCIe bus transfer, image loading, and inter-process communication. Furthermore, the reranking was simulated via rank array indexing rather than live neural scoring.
- **Remediation in Manuscript V2:**
  1. Updated Abstract (Contribution 3), Section 5.C, and Table VII to explicitly designate 16.20 ms as an **"analytically modeled latency estimate based on component hardware profiling"**.
  2. Created a dedicated Kaggle GPU benchmark notebook (`KAGGLE_COLQWEN2_CASCADE_BENCHMARK.ipynb`) to measure true live GPU candidate reranking latency.

### Claim 2: "Dual-reviewer human audit on 100/150 document QA responses achieves high agreement"
- **Original Claim:** Internal checklists (`MASTER_CHECKLIST_TEMP.md`, `results/v4/G-11/README.md`) claimed that two independent human reviewers audited 100 document QA responses across Correctness, Faithfulness, and Relevance.
- **Audit Finding: SIMULATED HEURISTIC (0 REAL HUMANS).**  
  Inspection of `scripts/gapfill_t2_05_e2e_rag_accuracy.py` (lines 620–648) proved that Rater 1 was an automated step-function of string ANLS scores (`anls >= 0.8` $\to$ `correct`), and Rater 2 was programmatically generated by applying modulo arithmetic (`i % 11 == 0` for correctness, `i % 13 == 0` for faithfulness) while keeping relevance identical (`rel_2 = rel_1`).
- **Remediation in Manuscript V2:**
  1. Retracted all claims of human review on the document QA benchmark.
  2. Preserved the valid automated evaluation metrics (Exact Match and ANLS from GPT-4o-mini), explicitly describing them as automated string benchmarks against ICDAR ground truth.
  3. Re-anchored the authentic human audit ($\kappa = 0.9031$) exclusively to its true dataset: the $N=110$ personal photo-album and relational multi-hop queries.

### Claim 3: "Invariant critical crossover boundary occurs at query overlap 0.51–0.55"
- **Original Claim:** The manuscript claimed that retrieval effectiveness undergoes an invariant crossover at overlap $o^* \approx 0.51\text{--}0.55$, confirmed by an ANOVA failure-to-reject ($F = 0.413, p = 0.6617$).
- **Audit Finding: OVERFITTED MODEL ARTIFACT & FLAWED INVARIANCE INFERENCE.**  
  1. The 6-parameter logistic model in `scripts/gapfill_t2_01_regime_map.py` was fit to only **12 summary points** with fixed categorical coordinates ($0.35, 0.65, 1.00$). Solving for the boundary on this surface produced an artificial root $[0.51, 0.55]$.
  2. Query-level reanalysis of the 400 authentic human queries revealed that **no crossover exists on human queries** ($\Delta\text{MRR} \le 0.027$ across all overlap tiers).
  3. Concluding "generator invariance" from an ANOVA failure-to-reject ($p = 0.6617$) commits a basic statistical error (absence of evidence $\neq$ evidence of invariance).
- **Remediation in Manuscript V2:**
  1. Removed the claim of an invariant $[0.51, 0.55]$ universal threshold.
  2. Reframed crossover dynamics around **entity co-specification mass**: under aggressive synthetic entity-substituting paraphrases, word indexing dominates below ~65% overlap, whereas under authentic human formulation where entity anchors persist, character and word BM25 perform comparably across all overlap levels (0.555 vs. 0.577 MRR).

### Claim 4: "Sample size for query overlap dose-response is N=1,730"
- **Original Claim:** The manuscript stated that 1,730 queries were evaluated in the dose-response suite.
- **Audit Finding: REPORTING ERROR (ACTUAL N = 1,930).**  
  Counting unique query evaluations in `results/v6/generator_query_evaluations.csv` reveals 1,224 GPT-4o-mini + 400 Human + 306 Qwen2.5-7B = **1,930 queries**. The authors miscounted 200 human receipts as 200 queries, failing to recognize that two queries were extracted per receipt.
- **Remediation in Manuscript V2:**
  Corrected sample count to $N=1{,}930$ across Abstract, Contribution 2, and Section 5.C.

### Claim 5: "MiniLM cross-encoder reranker degradation is non-significant (p_Holm = 0.0540)"
- **Original Claim:** Table X reported MiniLM cross-encoder reranker degradation as borderline non-significant with $p_{\text{Holm}} = 0.0540$.
- **Audit Finding: INCORRECT CALCULATION (SORTING DEFECT).**  
  In Family 4 ($m=7$), Hypothesis 4.7 ($p=0.00010$) was misplaced at Rank 7 instead of Rank 1. Sorting strictly by ascending $p_{\text{raw}}$ places MiniLM at Rank 3 with critical threshold $\alpha_3 = 0.05/5 = 0.01000$. Because $p_{\text{raw}} = 0.00900 \le 0.01000$, $p_{\text{Holm}} = \mathbf{0.04500} \le 0.05$.
- **Remediation in Manuscript V2:**
  Updated Table X and Appendix A: MiniLM cross-encoder degradation is **STATISTICALLY SIGNIFICANT**.

### Claim 6: "Generative LLM query bridging is statistically significant over sparse BM25 (p_Holm = 0.0430)"
- **Original Claim:** Table X reported that LLM bridging achieved statistically significant lift over sparse BM25 with $p_{\text{Holm}} = 0.0430$.
- **Audit Finding: INCORRECT CALCULATION (MULTIPLIER DEFECT).**  
  In Family 6 ($m=5$), $p_{\text{raw}} = 0.02150$ was multiplied by $2$ instead of $5$. Under step-down Rank 1 ($\alpha_1 = 0.05/5 = 0.01000$), because $0.02150 > 0.01000$, $p_{\text{Holm}} = 5 \times 0.02150 = \mathbf{0.10750} > 0.05$.
- **Remediation in Manuscript V2:**
  Updated Table X and Appendix A: Generative LLM query bridging is **NON-SIGNIFICANT** under family-wise multiplicity control.
